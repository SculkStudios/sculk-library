# Documentation Architecture

Documentation is a product. It is generated from the same sources that produce the framework, so
it cannot drift from what ships. Evidence and measurements: `docs/research/g-docs-spike.md`.

## Shell

Astro Starlight (0.42.x, Astro ≥ 7.2.10), deployed as static assets on Cloudflare Workers with
Bun, as today. The spike built the alternative (TanStack Start + MDX) in under two hours: it works,
but every shell feature Starlight ships is hand-built there, and its client JavaScript floor is
roughly 3.5× larger before any content exists. Both frameworks are pre-1.0; Starlight has the
larger production footprint.

The four Sculk-specific pipelines below are framework-agnostic. If the shell ever moves, they
move unchanged (ADR-0016).

## Pipelines

### Manifest

`sculk-manifest.json` is generated by a Gradle task from the committed `.api` dumps and the
`@SculkStable / @SculkExperimental / @SculkInternal`, `@SinceMinecraft`, `@Platforms` and
`@Requires` annotations (see `API_POLICY.md`). It is published as a static asset per Sculk major.

```jsonc
{
  "schema": 1,
  "sculk": "6.0.0",
  "minecraft": { "supported": ["1.21.4", "1.21.11", "26.1.2", "26.2", "26.3"], "latestTested": "26.3" },
  "modules": { "sculk-inventory": { "artifact": "studio.sculk:sculk-inventory", "sizeKiB": 0, "dependsOn": ["sculk-core", "sculk-text", "sculk-items"] } },
  "symbols": [{
    "symbol": "studio.sculk.inventory.menu",
    "module": "sculk-inventory",
    "stability": "stable",
    "since": { "sculk": "6.0.0", "minecraft": "1.21.4" },
    "minecraft": { "native": "1.21.4", "fallback": null },
    "platforms": { "paper": "native", "folia": "native", "canvas": "native", "velocity": "unavailable" },
    "threading": "entity",
    "page": "inventory/menus",
    "source": "sculk-inventory/src/main/kotlin/studio/sculk/inventory/Menu.kt#L40",
    "api": "https://api.sculk.studio/6/sculk-inventory/studio.sculk.inventory/menu.html"
  }]
}
```

Consumers: sidebar generation (grouped by module, badged by stability), the per-page
compatibility strip, the compatibility-checker playground, and the `/create` module picker. A
manifest symbol whose `page` has no MDX file fails the docs build. Page frontmatter carries only
`title`, `description` and `module`; everything else is looked up by slug so each fact lives once.

### Snippets

Code in documentation is imported, never pasted. Examples under `examples/*` are compile gates;
they carry `// #region name` / `// #endregion` markers, and a remark plugin replaces a fence such
as ` ```kotlin snippet=examples/basic-plugin/src/main/kotlin/BasicPlugin.kt#menu ` with the region
at build time, markers stripped and dedented. A missing file or region fails the build. Regions
are referenced by name only; line ranges are not allowed in published content. Because
substitution happens before highlighting, no source text reaches the client bundle.

### Versions

The repository always builds the current major at `/`. Archived majors are built from their git
tag in CI with `base: '/vN'` and merged into one assets upload; `versions.json` drives the header
switcher. One Pagefind index per version. The `starlight-versions` plugin is not used: it copies
content into the repository and describes itself as early development.

### Selectors

Three stores (nanostores): Sculk version from the URL base, Minecraft version and platform from
`localStorage`, set from header selects. `<Platform only="folia">` and `<Since minecraft="26.1">`
render every variant into HTML with data attributes and hide with CSS, so search and crawlers see
all content and filtering needs no hydration. The compatibility strip on each page is the manifest
entry evaluated against the selected version and platform.

## Search

Pagefind, built into Starlight, with `version` and `module` filters injected from the page
template. Algolia DocSearch is a vendor dependency with an eligibility review; Orama adds a
client-side index download. Both remain possible through the `Search` component override.

## Playgrounds

React islands (`@astrojs/react`, `client:visible`), self-contained, state via nanostores:
MiniMessage preview, command-tree visualizer, inventory layout visualizer, compatibility checker.
Each must be correct before it is pretty; a playground that disagrees with the framework is a bug.

## Project generator

`/create` is a Starlight page with one React island. The archive is built in the browser with
`fflate` (MIT) from templates plus the manifest's module list and versions. It ships the Gradle
wrapper, `paper-plugin.yml` with `folia-supported` from the platform choice, a Kotlin entry point,
`.gitignore` and a README. No Worker endpoint. Setting the executable bit on `gradlew` inside the
archive is unverified and is tested before launch.

## Information architecture

Start · Learn · Guides · Concepts · Reference · Recipes · Migration · Advanced, as in the directive.
Every subsystem page is written in three layers: a five-minute path, the production guide, then
architecture and reference. Reference pages are generated from the manifest and Dokka.

## Build gates

The docs build fails on: a manifest symbol without a page, a snippet region that does not exist,
a broken internal link, a page without `module` in a module section, or a Workers assets file
count above the plan limit. Documentation snippets compile because they are the examples.

## Prerequisite

Upgrade Starlight from 0.41.6 to 0.42.x (Astro ≥ 7.2.10) before adopting the sidebar plugins.
