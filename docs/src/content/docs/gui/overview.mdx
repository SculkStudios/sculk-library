```kotlin
val menu = gui("<value>Shop</value>") {
    size = 27
    border(Material.GRAY_STAINED_GLASS_PANE) { name = " " }

    item(13) {
        material = Material.DIAMOND_SWORD
        name = "<value>Sharp Sword</value>"
        lore("<dim>250 coins")
        onClick { reply("<value>Bought.</value>"); close() }
    }
}

sculk.menus.open(menu, player)
```

## Opening

Menus are opened through `sculk.menus`, never on the `Gui`:

```kotlin
val session = sculk.menus.open(menu, player)
```

A `Gui` is a **description**. Showing one needs a scheduler (so the inventory opens on the thread
that owns the player), a coroutine scope (for animations), and registration (so clicks are
cancelled). A menu that skipped registration is a chest whose contents are free to take, which is
why the ability to open one without it no longer exists.

## Clicks

Every click is **cancelled before your handler runs**, so a handler that throws cannot leave the
click applied and turn a bug into item duplication.

```kotlin
item(11) {
    material = Material.EMERALD
    onLeftClick { reply("<value>Bought one.</value>") }
    onRightClick { reply("<value>Bought a stack.</value>") }
    onShiftClick { reply("<value>Bought everything.</value>") }
    onClick { /* any click type not handled above */ }
}
```

Inside a handler you have `player`, `clickType`, `slot`, the raw `event`, and the `session`:

```kotlin
onClick {
    if (clickType.isShiftClick) session.nextPage() else close()
}
```

## Input slots

By default every slot is locked. Mark one interactive to let players put things in:

```kotlin
item(22) {
    material = Material.AIR
    interactive()
}
```

Drags are handled too — a drag touching any locked slot in the menu is refused entirely, because
cancelling part of a drag is not possible.

## Per-viewer content

```kotlin
item(15) {
    dynamicContent { viewer ->
        item(Material.PLAYER_HEAD) {
            name = "<value>${viewer.name}</value>"
        }
    }
}
```

Resolved when the menu is built for each player, so one `Gui` serves everyone.

## Layout helpers

```kotlin
gui("<value>Menu</value>") {
    size = 54
    fill(Material.BLACK_STAINED_GLASS_PANE) { name = " " }
    border(Material.GRAY_STAINED_GLASS_PANE) { name = " " }
    items(listOf(10, 11, 12)) { material = Material.CHEST }
}
```

```kotlin
border(Material.GRAY_STAINED_GLASS_PANE, style = GuiBorderStyle.Horizontal, skip = listOf(4))
```

## Sessions

`open` returns a live session:

```kotlin
val session = sculk.menus.open(menu, player)

session.refresh(13)
session.refreshAll()
session.state["page"] = 2
session.close()
```

```kotlin
sculk.menus.sessionFor(player)
```

## Switching menus

From inside a handler:

```kotlin
onClick { open(otherMenu) }
```

## Container types

```kotlin
gui("<value>Anvil</value>") {
    type = InventoryType.HOPPER
}
```

## Confirmation

```kotlin
val confirm = confirmMenu("<danger>Delete your home?</danger>") {
    confirm {
        material = Material.LIME_WOOL
        name = "<value>Yes</value>"
        onClick { homes.delete(player); close() }
    }
    cancel {
        material = Material.RED_WOOL
        name = "<danger>No</danger>"
        onClick { close() }
    }
}
```

## Cleanup

Sessions are dropped on close and on quit. Closing the platform closes every open menu. You do not
need to track them.
