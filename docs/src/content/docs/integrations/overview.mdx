---
title: Integrations
description: Optional adapters for common server plugins.
---

`sculk-integrations` provides lightweight adapters for common plugins without making them required dependencies.

Enable integrations in your plugin's subsystem block:

```kotlin
class MyPlugin : SculkPlugin() {
    override fun setup() { /* sculk.integrations.* */ }
}
```

## PlaceholderAPI

```kotlin
val papi = sculk.integrations.placeholderApi()
papi.onSuccess { integration ->
    player.sendMini(integration.parse(player, "<green>Hello %player_name%"))
}
```

## Vault Economy

```kotlin
sculk.integrations
    .vaultEconomy()
    .onSuccess { economy ->
        economy.deposit(player, 100.0)
    }
```

## LuckPerms

```kotlin
sculk.integrations
    .luckPerms()
    .onSuccess { luckPerms ->
        val group = luckPerms.primaryGroup(player.uniqueId)
    }
```

`primaryGroup` reads the **cache only**, so somebody who is not loaded answers null. For an answer that
is correct for anyone, online or not, use the suspending reads:

```kotlin
val groups = luckPerms.groups(uuid).getOrNull().orEmpty()      // every effective group
val staff = luckPerms.hasPermission(uuid, "myplugin.staff").getOrNull() == true
```

Both load the user if they are not cached, which is why they suspend. Blocking on that load is the
mistake worth naming: LuckPerms may be backed by a remote database, and a `.get()` from a join
listener stalls the server tick for as long as that database takes.

:::note[Groups, not nodes]
`groups` returns what LuckPerms itself would say the player has — **inheritance, contexts, temporary
grants and negations all already applied**. Reading `InheritanceNode`s off a user and taking their
names looks equivalent and is not: it ignores all four, and happily reports a group the player does
not actually have.
:::

Unavailable plugins return `SculkResult.Failure`; they do not crash plugin startup.

## Packet backends

PacketEvents and ProtocolLib are handled by packet modules, not `sculk-integrations`, because they need their own size and lifecycle policy.

- Use `sculk-packets-packetevents` for new packet-heavy plugins.
- Use `sculk-packets-protocollib` when a server already depends on ProtocolLib.
- Install PacketEvents or ProtocolLib on the server; Sculk does not shade them.

See the packet docs for backend setup and thread-safety rules.
