## What it looks like

```kotlin
import net.kyori.adventure.text.Component
import org.bukkit.event.EventHandler
import org.bukkit.event.Listener
import org.bukkit.event.player.PlayerJoinEvent
import studio.sculk.execution.EntityResult
import studio.sculk.execution.withAsync
import studio.sculk.paper.SculkPaperPlugin
import studio.sculk.paper.withEntity
import studio.sculk.task.repeating
import java.nio.file.Files
import java.util.UUID

class MyPlugin : SculkPaperPlugin(), Listener {
    override suspend fun start() {
        server.pluginManager.registerEvents(this, this)
        sculk.scope.repeating(periodTicks = 20L * 60 * 10) {
            server.dispatchCommand(server.consoleSender, "save-all")
        }
    }

    @EventHandler
    fun onJoin(event: PlayerJoinEvent) {
        val player = event.player
        sculk.scope.launch {
            val visits = withAsync { readVisits(player.uniqueId) }
            val greeted = withEntity(player) {
                player.sendMessage(Component.text("Welcome back. This is visit $visits."))
            }
            if (greeted is EntityResult.Gone) logger.info("${player.name} left before the greeting.")
        }
    }

    // Blocking file I/O, which is why it runs inside withAsync.
    private fun readVisits(id: UUID): Int {
        val file = dataFolder.toPath().resolve("visits/$id")
        return if (Files.exists(file)) Files.readString(file).trim().toInt() else 0
    }
}
```

`withAsync` runs off every game thread, `withEntity` runs on whichever thread owns the player at
that moment, and the outcome says whether the player was still there. On Paper both game
contexts are the main thread; on Folia and Canvas they are not, and the code does not change.

## What exists today

| Module | What it gives you |
| --- | --- |
| `sculk-core` | `SculkResult`, failures, `ResourceScope`, lifecycle, capabilities, `MinecraftVersion`, clock, services, diagnostics |
| `sculk-coroutines` | Execution contexts, `withGlobal` / `withRegion` / `withEntity` / `withAsync`, scopes, tasks |
| `sculk-platform-api` | The runtime contract every platform implements |
| `sculk-paper` | `Sculk.attach`, `SculkPaperPlugin`, the Paper, Folia and Canvas runtime |
| `sculk-canvas` | Canvas regionized data, extra ownership checks, async world unload |
| `sculk-velocity` | `SculkVelocity.attach`, `SculkVelocityPlugin`, the proxy runtime |
| `sculk-testkit` | `FakeExecutor`, `FakeRuntime`, `FakeClock` |
| `sculk-text` | Themes and safe MiniMessage rendering (API settling) |
| `sculk-config` | Typed YAML configuration (API settling) |

Commands, events, menus, items, presentation, data and the integrations are designed but not
built yet. The [roadmap](/reference/roadmap/) lists every module and its state.
