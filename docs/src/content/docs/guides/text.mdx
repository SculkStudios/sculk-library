`sculk-text` (package `studio.sculk.text`) turns templates into Adventure components. It depends
only on `sculk-core` and is platform-neutral: the server provides Adventure, and the module runs on
Paper's Adventure 4.x and on the Adventure 5.2 that Paper 26.2+ and Velocity 4 ship.

```kotlin
dependencies {
    implementation("studio.sculk:sculk-text:6.0.0-SNAPSHOT")
}
```

## Templates are trusted, values are not

A template comes from your code, your configuration or a translation file, and may contain any
MiniMessage. A value (a player name, a database row, another plugin's output) is not trusted. It
enters a message only as an unparsed placeholder, or as a component that is already built, so
`<red>` inside a player's name is printed, not obeyed.

```kotlin
import net.kyori.adventure.text.Component
import org.bukkit.entity.Player
import studio.sculk.text.Text

private val text = Text()

fun greet(player: Player): Component = text.render("<primary>Welcome, <name>!", "name" to player.name)
```

Never build a template by substituting a value into it, for example with `replace` or string
interpolation, before rendering: that is exactly the injection this design exists to prevent.

## Themes

A theme gives semantic names to styles: templates say `<primary>`, `<muted>` or `<danger>` instead
of a colour, so restyling a plugin is one edit to the theme rather than a search through every
message. Theme styles are expanded in the template before parsing, never in values, so a value
cannot pull in a style. A style name may not shadow a MiniMessage tag, and a placeholder may not
share its name with a style. The default theme defines `primary`, `secondary`, `value`, `muted`,
`success`, `warning` and `danger`; each plugin is expected to choose its own colours.

## Measuring text

`GlyphWidths` holds the pixel advances of a font's glyphs, with a table for Minecraft's default
font, for measuring and centring components in chat.

## Translations and plurals

Ship your messages in the plugin jar as `messages_<language>[_<COUNTRY>].properties` files (UTF-8)
under one folder, and register them once:

```kotlin
import net.kyori.adventure.key.Key
import net.kyori.adventure.text.Component
import studio.sculk.getOrThrow
import studio.sculk.text.TranslationFiles
import java.util.Locale

// in start()
val messages = TranslationFiles.load(
    classLoader = javaClass.classLoader,
    resources = "lang",
    overrides = dataPath.resolve("lang"),
    defaultLocale = Locale.ENGLISH,
).getOrThrow()
messages.register(sculk.scope, Key.key("myplugin", "messages"))

player.sendMessage(Component.translatable("shop.welcome"))
```

A translatable component renders in each player's own locale. A lookup falls back from the exact
locale (`nl_BE`) to its language (`nl`) to the default locale; a key that no bundle has shows as
its own name, so a gap is visible.

- **Operator overrides.** A server owner changes one message by putting just that key in
  `plugins/<YourPlugin>/lang/messages_<language>.properties`. Every other key keeps the jar's text,
  including keys a later version of your plugin adds.
- **Reload.** `messages.reload()` reads every file again. It applies as a whole or not at all: a
  file that fails to read leaves the previous messages in place and returns the failure.
- **Lifetime.** The registration ends with the scope you pass, so a plugin that stops leaves
  nothing behind in Adventure's global translator.
- **Plurals.** A key with forms, `coins.one` and `coins.other` (and `zero`, `two`, `few`, `many`
  where the language has them), takes its count from the first numeric argument:
  `Component.translatable("coins", TranslationArgument.numeric(3))`, available to the template as
  `<count>`. The forms follow the CLDR 49 rules of every locale CLDR lists; a language it does not
  list uses only `other`.

Arguments are values: they fill tags as components or unparsed text and are never parsed as
MiniMessage. Translated templates are trusted like any other template: translators may style them
and use theme styles, players may not.
