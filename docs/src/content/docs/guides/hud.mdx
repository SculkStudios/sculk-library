`sculk-presentation` (package `studio.sculk.presentation`) builds every part of a HUD from
templates and [placeholders](/guides/placeholders/), and each player sees their own values.

```kotlin title="build.gradle.kts"
dependencies {
    implementation("studio.sculk:sculk-presentation:6.0.0-SNAPSHOT")
}
```

## A HUD

```kotlin
import studio.sculk.placeholder.PlaceholderRegistry
import studio.sculk.presentation.Huds
import studio.sculk.presentation.Update
import studio.sculk.presentation.hud

// in start():
val placeholders = PlaceholderRegistry(sculk.scope)
val huds = Huds(this, sculk.scope.resources, placeholders)

val layout = hud {
    actionBar("<muted>Balance: <value><economy_balance>")
    bar("event", "<warning>Event ends in <event_left>", progress = { event.progress() }, update = Update.Every(20))
    tabList(header = "<primary>Sculk Network", footer = "<muted>play.sculk.studio")
    sidebar("<primary>Sculk", "Online: <server_online>", "Rank: <player_rank>")
}

sculk.events.listen<PlayerJoinEvent> { event -> huds.show(event.player, layout) }
```

A layout has at most one action bar, tab list and sidebar, any number of boss bars with different
ids, and up to fifteen sidebar lines.

## What redraws, and when

- **`Update.OnChange`** (the default): a surface redraws when a placeholder it used signals a
  change, for everyone or for this player. Sculk records which placeholders each surface used as it
  renders, so nothing has to be declared, and a change to one placeholder redraws only what showed
  it.
- **`Update.Every(ticks)`**: also on an interval, for values that drift without a signal, such as a
  countdown or a boss bar's progress.
- **`Update.Manual`**: only when you call `hud.refresh()`.
- Whatever triggers a redraw, nothing is sent when the result equals what the player already sees.
  An idle HUD schedules no work at all; the action bar alone is resent every two seconds while
  shown, because the client fades it.
- `showWhen = { player -> ... }` on any surface hides it while false; it is checked at least once a
  second.

A HUD runs on its player's thread, ends when they leave, and every HUD of a `Huds` ends with its
scope. `huds.show` replaces a player's previous HUD from the same `Huds`.

## Titles

A title is shown once and fades by itself, so it is not part of a layout:

```kotlin
huds.title(player, "<primary>Round <game_round>", "<muted>Good luck", Title.Times.times(fadeIn, stay, fadeOut))
huds.clearTitle(player)
```

Both templates are rendered with the `Huds`'s placeholders for that player, and both calls work
from any thread. A player needs no HUD to be shown a title.

## Nametags and below-name lines

A layout can also set how other players see this player's name: a prefix and suffix around it,
above their head and in the tab list, and a line under it.

```kotlin
val layout = hud {
    nametag(prefix = "<rank_prefix> ", suffix = " <muted>[<player_level>]")
    belowName("<danger><player_health> ❤")
}
```

They are rendered for the player whose name it is, so every viewer sees the same text, and redraw
like any other surface when a placeholder they used changes. Text that differs per viewer needs
`sculk-presentation-packets`.

Sculk writes one team and one below-name score per player to the server's main board, and copies
them onto the board of any player who has a Sculk sidebar, so they see them too. If another plugin
has already put the player in a team, Sculk leaves that team alone and shows its nametag once the
player has left it; the below-name line likewise waits while another plugin's objective holds that
slot.

<Aside type="caution">
  A player with a Sculk sidebar sees Sculk's board, not the main board, so teams that other plugins
  or `/team` keep on the main board (their prefixes, colours and collision rules) do not show for
  that player. Sculk's own nametags and below-name lines do.
</Aside>

## The sidebar and other plugins' boards

A player sees one scoreboard. The sidebar takes the player's board only from the server's main
board; if another plugin has given the player its own board, Sculk's sidebar waits and shows once
that board is gone, and when the HUD closes the player gets back the board they had.

The sidebar needs Bukkit scoreboards, which Paper and Canvas have and Folia does not:
`huds.sidebarAvailable` says which, and showing a layout with a sidebar, nametag or below-name
line on Folia returns an `UnsupportedCapability` failure. The action bar, boss bars, tab list and
titles work everywhere.

<Aside>
  Sculk's `integration-tests/hud` suite shows a HUD to a real client on every supported Paper
  version, Folia and Canvas, changes a placeholder, hands the player another plugin's board and
  team, shows a title and closes it, checking what the client receives each time.
</Aside>
