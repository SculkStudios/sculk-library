Everything below is one file. It is the same shape as
[`examples/basic-plugin`](https://github.com/SculkStudios/sculk-library/tree/main/examples/basic-plugin),
which CI compiles against the real API, so it cannot quietly drift.

## The plugin

```kotlin
class MyPlugin : SculkPlugin() {
    override fun setup() {
        +command("hello") {
            description = "Says hello."
            player { reply("<green>Hello, <name>.", "name" to player!!.name) }
        }
    }
}
```

```yaml
# src/main/resources/paper-plugin.yml
name: MyPlugin
version: '1.0.0'
main: com.example.MyPlugin
api-version: '1.21'
```

That is a working plugin. `onEnable` and `onDisable` are **final** — the framework starts and stops
itself, and everything you register is closed in reverse order on disable.

## A theme

Write messages against meaning rather than colour, so changing the look is one edit:

```kotlin
class MyPlugin : SculkPlugin() {
    override val theme = SculkTheme(
        mapOf(
            "value" to ThemeStyle.Gradient(listOf("#8be9fd", "#50fa7b")),
            "danger" to ThemeStyle.Solid("#ff5f5f"),
            "dim" to ThemeStyle.Solid("#6272a4"),
        ),
    )

    override fun setup() {
        +command("hello") {
            player { reply("<value>Hello, <name>.</value>", "name" to player!!.name) }
        }
    }
}
```

:::caution
`<name>` is a **placeholder value**, passed separately. Never build the message with
`"Hello, ${player.name}"` — a player-controlled string parsed as markup is an injection hole. See
[the trust boundary](/text/placeholders/).
:::

## A config

The data class *is* the file. There is no `config.yml` in your resources.

```kotlin
@Serializable
@ConfigFile("settings.yml")
@Comment("MyPlugin settings.")
data class Settings(
    @Comment("How many diamonds /gift hands out.")
    @Min(1)
    val giftAmount: Int = 3,
)
```

```kotlin
val settings = sculk.config.load<Settings>().getOrThrow()
```

On first load it writes the defaults out with their comments. On later loads it adds keys the file
is missing — and never removes anything you or a server owner put there.

## A service

Put your own objects where the rest of your plugin can reach them:

```kotlin
class GiftService(private val amount: Int) {
    fun amountFor(player: Player): Int = amount
}
```

```kotlin
override fun setup() {
    val settings = sculk.config.load<Settings>().getOrThrow()
    sculk.services.register(GiftService(settings.giftAmount))
}
```

```kotlin
val gifts = sculk.services.get<GiftService>()
```

Keyed by type, so a rename is a compile error rather than a runtime one. See
[Services](/platform/services/).

## A menu

```kotlin
+command("gift") {
    description = "Opens the gift menu."
    player {
        val viewer = player!!
        sculk.menus.open(
            gui("<value>A gift</value>") {
                size = 27
                border(Material.GRAY_STAINED_GLASS_PANE) { name = " " }
                item(13) {
                    material = Material.DIAMOND
                    amount = sculk.services.get<GiftService>().amountFor(viewer)
                    name = "<value>Take it</value>"
                    lore("<dim>Click to close.")
                    onClick { close() }
                }
            },
            viewer,
        )
    }
}
```

Menus are opened through `sculk.menus`, not on the `Gui` itself. A menu cannot be shown without a
scheduler, a coroutine scope for its animations, and somewhere to register itself — and a menu that
never registered is one whose clicks are never cancelled.

## Putting it together

```kotlin
class MyPlugin : SculkPlugin() {
    override val theme = SculkTheme(
        mapOf(
            "value" to ThemeStyle.Gradient(listOf("#8be9fd", "#50fa7b")),
            "danger" to ThemeStyle.Solid("#ff5f5f"),
            "dim" to ThemeStyle.Solid("#6272a4"),
        ),
    )

    override fun setup() {
        val settings = sculk.config.load<Settings>().getOrThrow()
        val gifts = sculk.services.register(GiftService(settings.giftAmount))

        +command("gift") {
            description = "Opens the gift menu."
            player {
                val viewer = player!!
                reply("<value>Here you go, <name>.</value>", "name" to viewer.name)
                sculk.menus.open(giftMenu(gifts.amountFor(viewer)), viewer)
            }
        }
    }
}
```

You get `/help` for free — generated from the same specs Brigadier was given and filtered by
permission, so it cannot drift from what the server actually accepts.
