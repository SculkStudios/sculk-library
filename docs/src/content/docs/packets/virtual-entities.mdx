---
title: Virtual entities
description: Display entities that exist only in a client's view.
---

The server has no entity. Nothing ticks, nothing is tracked, nothing is saved, and a crash cannot
leave anything behind.

```kotlin
val entities = sculk.packets.getOrNull()?.virtualEntities ?: return

val id = entities.reserveEntityId()
entities.spawnTextDisplay(player, id, location, messages.render("<value>Hello</value>"))
entities.updateTextDisplay(player, id, messages.render("<value>Goodbye</value>"))
entities.despawn(player, listOf(id))
```

Most of the time you want [holograms](/visual/holograms/) or [nametags](/visual/nametags/), which
are built on this. Reach for it directly when you need something they do not do.

## Entity ids

```kotlin
val id = entities.reserveEntityId()
```

Counts **down** from `Int.MAX_VALUE`, because the server counts up. A shared counter is the only
way two callers avoid picking the same id — never invent one yourself.

## Mounting

```kotlin
entities.mount(viewer, vehicleId = player.entityId, passengerIds = listOf(displayId))
```

This is how a nametag tracks its wearer. A mounted entity is interpolated by the client, so it
follows exactly; a teleport loop visibly swims behind the player at anything above a walk.

## Style

```kotlin
TextDisplayStyle(
    billboard = Billboard.CENTER,
    scale = 1.0f,
    backgroundArgb = 0,      // fully transparent — no plate
    shadowed = true,
    seeThrough = false,
    lineWidth = 200,
)
```

:::note
`backgroundArgb = 0` is the only way to get no background plate. Turning off a "default background"
flag alone still leaves the client drawing one — which is why the colour and the flag are a single
setting here rather than two you can half-configure.
:::

## No backend

```kotlin
entities.available
```

Without PacketEvents, `available` is false and every call returns a named failure rather than
throwing. Your plugin still enables.

ProtocolLib reports unavailable for virtual entities specifically: its entity-metadata
serialisation is where version fragility lives, and a half-implementation that breaks on the next
Minecraft release is worse than an honest "not supported".
