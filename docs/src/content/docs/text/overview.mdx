title: Messages
description: Rendering text, and the one place a String becomes a Component.
---

`SculkMessages` is the renderer. It is the only place in Sculk where a `String` becomes a
`Component`, which is what makes the [trust boundary](/text/placeholders/) enforceable rather than
a convention you have to remember.

You get one from the platform:

```kotlin
sculk.messages.send(player, "<value>Welcome back.</value>")
```

Inside a command handler it is already there:

```kotlin
+command("hello") {
    player { reply("<value>Hello, <name>.</value>", "name" to player!!.name) }
}
```

## Rendering

```kotlin
val component = messages.render("<danger>Denied.")
```

```kotlin
messages.send(audience, "<value>Saved.</value>")
messages.send(audience, listOf("<value>Line one</value>", "<dim>Line two</dim>"))
messages.actionBar(player, "<danger>Low health</danger>")
messages.title(player, "<value>Round 2</value>", "<dim>fight</dim>")
```

Every one takes placeholder values as trailing pairs:

```kotlin
messages.send(player, "<value><n></value> players online.", "n" to online.toString())
```

## Item text

Item names and lore are italic by default in vanilla, which quietly undoes careful formatting:

```kotlin
messages.renderItemText("<value>Cursed Blade</value>")
```

This turns italics off unless the template asks for them. The item builders use it already, so
`name(…)` and `lore(…)` are handled for you.

## Server-wide defaults

A drop shadow is set once, on the plugin:

```kotlin
class MyPlugin : SculkPlugin() {
    override val shadow = 0x99000000.toInt()
}
```

It is applied *if absent*, so a message that sets its own shadow always wins.

## An instance, not a global

`SculkMessages` is constructed per plugin and carries that plugin's [theme](/text/theme/). Two
plugins on one server can have entirely different palettes and neither can change the other's —
which the previous server-wide mutable object could not offer.
