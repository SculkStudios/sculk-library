---
title: Modules
description: What each module does, and how to depend on only what you need.
---

Sculk is sixteen modules. Depending on `sculk-platform` gets all of them, which is what most
plugins want.

| Module | What it is for |
| --- | --- |
| `sculk-platform` | The one-line install. `SculkPlugin`, the service registry, the scheduler implementation, event registration. Re-exports everything below. |
| `sculk-common` | `SculkResult`, `SculkHandle`, the scheduler contract, the coroutine scope, cron and repeating tasks, directory watching. Depends on nothing. |
| `sculk-text` | The theme, the renderer, text measurement, localisation bundles. |
| `sculk-config` | Typed YAML: generated defaults, validation, migrations, hot reload. |
| `sculk-commands` | Command specs as data, the Brigadier adapter, generated help. |
| `sculk-gui` | Chest and container menus. |
| `sculk-data` | Repositories, the query DSL, schema migration, caching. |
| `sculk-hud` | Sidebar, action bar, tab list, boss bars. |
| `sculk-visual` | Particles, sounds, timelines, holograms, nametags. |
| `sculk-items` | Data-component item builders, persistent data, descriptors. |
| `sculk-series` | Registry lookups with aliases. |
| `sculk-packets-api` | Backend-neutral packets. `-packetevents` and `-protocollib` implement it. |
| `sculk-discord` | Backend-neutral Discord: messages as data, slash commands, interactions, webhooks. `-jda` implements it. Needs no Minecraft server. |
| `sculk-integrations` | Optional PlaceholderAPI, Vault and LuckPerms adapters. |
| `sculk-bom` | Version alignment for à-la-carte use. |

## Dependency order

```
common          ← (nothing)
config          ← common
text            ← common
series          ← common
items           ← common, text, series
commands        ← common, text
gui             ← common, text, items
data            ← common, config
packets-api     ← common
packets-*       ← packets-api
visual          ← common, series, text, packets-api
hud             ← common, text
integrations    ← common
platform        ← everything
```

A module depends only on what it uses. Two edges are load-bearing:

- **`sculk-text` does not depend on `sculk-config`.** It would put the whole config system on the
  compile classpath of menus, items and commands. The bundle loader reads YAML directly.
- **`sculk-visual` does not depend on a packet backend.** Holograms go through the neutral
  `VirtualEntityService`. When they did import PacketEvents directly, ProtocolLib could not serve
  holograms at all.

## Picking modules

Use the BOM so versions cannot drift apart:

```kotlin
dependencies {
    implementation(platform("com.github.SculkStudios.sculk-library:sculk-bom:5.0.0"))
    implementation("com.github.SculkStudios.sculk-library:sculk-commands")
    implementation("com.github.SculkStudios.sculk-library:sculk-gui")
}
```

Note that without `sculk-platform` you do not get `SculkPlugin`, and you are responsible for
constructing and closing whatever you use.

## Test fixtures

Two modules publish test doubles:

```kotlin
testImplementation(testFixtures("com.github.SculkStudios.sculk-library:sculk-common"))
testImplementation(testFixtures("com.github.SculkStudios.sculk-library:sculk-packets-api"))
```
