`sculk-items` is the standalone item API for Sculk Studio 2.0. It is used directly in plugins and by GUI builders for shared item metadata behavior.

```kotlin
val sword = item(Material.DIAMOND_SWORD) {
    name("<aqua>Starter Sword")
    lore("<gray>A clean starter weapon.", "", "<yellow>Right-click to inspect.")
    amount(1)
    enchant(Enchantment.SHARPNESS, 5)
    glint()
    unbreakable()
    customModelData(1001)
    pdc("starter_item", true)
}
```

String material keys are supported for config-driven workflows:

```kotlin
val icon = item("nether_star") {
    name("<aqua>Profile")
    lore("<gray>Click to view your profile.")
}
```

## Keys that come from config

Three parts of an item can be named by string, and a server owner will eventually mistype one. They
fail differently on purpose, by how much of the item depends on them:

| Call | Bad key | Why |
| --- | --- | --- |
| `item("diamond_sword")` | `SculkResult.Failure` | Without a material there is no item, so the caller has to decide. |
| `enchant("sharpnesss", 3)` | Logged, enchant skipped | A decoration. One typo should not fail a reward. |
| `model("bad key")` | Dropped | Same. |

Nothing here is silent — the enchantment path names the key in the log.

## GUI Integration

GUI items can use the same builder through `stack { }`:

```kotlin
item(13) {
    stack {
        material("nether_star")
        name("<aqua>Profile")
        lore("<gray>Click to view your profile.")
        customModelData(1001)
    }

    onClick {
        reply("<green>Opening profile...")
    }
}
```

## Player Heads

```kotlin
val head = skull {
    owner(player.uniqueId)
    name("<aqua>${player.name}")

}
```

## Safe Give Or Drop

Use `giveOrDrop` when rewards must never vanish because a player's inventory is full:

```kotlin
val reward = item("diamond") {
    name("<aqua>Vote Diamond")
}

val result = player.giveOrDrop(reward)

if (!result.fullyDelivered) {
    player.sendMessage("Some rewards were dropped at your feet.")
}
```

`given` and `dropped` are disjoint: `given` is only what the inventory accepted, and a stack that fit
partly appears in both at its own amount. Log and charge against `given` — counting the input as
delivered credits a player for items lying on the floor.

Call this from the server thread, or from the player's region thread on Folia-like servers. If the item is part of a database-backed reward flow, load and decide the reward asynchronously, then hand back to sync before touching the inventory.

## Modern components

The item builder writes Paper data components, with typed helpers (`food`, `rarity`, `itemName`,
`maxStackSize`) and a generic `component(type, value)` escape hatch for everything else. See
[Data components](/items/components/) for the full surface.
